9  スキルとフック

🟣 上級者向け

確認日：2026-11-15。スキルは再利用する手順、フックはイベントに結び付ける処理です。外部導入時は、どちらもソフトウェア依存として審査します。

9.1 スキルを作る

入口ファイル名は大文字のSKILL.mdです。旧カスタムコマンドも利用できます。新規手順は参照資料やスクリプトを同梱できるスキルを検討します。公式スキル仕様

.claude/skills/evidence-table/
├── SKILL.md
└── template.md

明示的に呼び出した場合だけ動く例です。

---
name: evidence-table
description: 公開論文の確認済みの記述から根拠表の下書きを作る。
disable-model-invocation: true
---
対象：$ARGUMENTS
1. 許された公開原文を読む。本文未確認なら抄録だけと明記する。
2. 原文にない数値や書誌情報は補完しない。
3. template.mdに沿い出典URL・位置・確認日を付ける。
4. 外部送信・公開は行わない。

template.mdには「対象集団／研究デザイン／主要結果／原文位置／制約」の列を用意します。

/evidence-table sources/public-paper.md

disable-model-invocationは自律的呼び出しの制御です。ファイルアクセスや通信は別の権限で制限します。補助スクリプト・動的シェル実行・依存パッケージも確認してください。

9.2 フックの入力とイベント

コマンド型フックの入力は通常標準入力のJSONです。$FILE、$COMMAND、$TOOL_NAMEが自動で渡る前提で書きません。公式フック仕様

イベント 用途 注意
PreToolUse 実行前判定 呼び出しをブロックできる
PostToolUse 整形や記録 実行済み操作は取り消せない
Stop 応答を終える際の検査 セッション終了とは別
SessionEnd セッション終了時の処理 復旧手段にはしない

9.3 JSON入力を処理する実例

データ転送方針としてWebFetchを禁止する単純な例です。全通信経路を遮断するものではありません。BashやMCPは別に制限します。.claude/settings.jsonの既存設定を残してマージします。

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "WebFetch",
      "hooks": [{
        "type": "command",
        "command": "python3 \"$CLAUDE_PROJECT_DIR/scripts/block_webfetch.py\"",
        "onFailure": "block"
      }]
    }]
  }
}

scripts/block_webfetch.py（Python 3が必要）：

import json
import sys

try:
    event = json.load(sys.stdin)
except (ValueError, TypeError):
    print("フック入力が不正です。停止します。", file=sys.stderr)
    raise SystemExit(2)

if not isinstance(event, dict):
    print("JSONオブジェクトが必要です。", file=sys.stderr)
    raise SystemExit(2)

if event.get("tool_name") == "WebFetch":
    print("この環境ではWebFetchを許可していません。", file=sys.stderr)
    raise SystemExit(2)

onFailure: blockは起動失敗やタイムアウトも止める現行設定です。古いCLIでは対応を確認してください。

9.4 終了コードと検証

構造化した判定JSONを出さない上のPreToolUse例では、終了0は成功、終了2はブロックです。他の非ゼロ終了はイベント・出力・onFailure等で扱いが変わります。「非ゼロなら常に止まる」「すべて無視される」は誤りです。

安全検査に|| trueや無条件のバックグラウンド実行を付けて失敗を隠しません。通知の失敗と安全検査の失敗を分けます。

  1. 自作入力で許可・拒否・不正JSONを確認する。
  2. スクリプト不存在・タイムアウト時に失敗方針が効くか確認する。
  3. Claude内でも無害な例でブロックを確認する。
  4. ゲート自身をAIが変更できない管理方法を検討する。
  5. ログにプロンプト全文・認証情報・患者情報を残さない。

完全なシェルを正規表現で安全判定するのは困難です。単語ブラックリストを最終防御にせず、権限とOS隔離を組み合わせます。
