15  ループエンジニアリング

🟣 上級者向け

ハーネスエンジニアリング（第14章）が、モデルを動かす環境の設計だとすれば、ループエンジニアリングは、エージェントを反復させる設計です。

1回の応答で終わらせず、次のような実行方式を使い分けます：

  • 定期実行
  • 自己ペース反復
  • スケジュール実行
  • バックグラウンド実行

本章では、長時間タスクや監視を自律化するためのループ設計を扱います。

15.1 ループエンジニアリングとは

ハーネスは環境、ループは反復です。両者は別物ではなく、補完関係にあります。

エージェントの基本ループは次の形で整理できます：

思考
  ↓
行動
  ↓
観察
  ↓
完了条件を満たすまで反復

これは、第1章で扱った「思考→行動→確認」ループの発展形です。

Important完了条件を先に決める

明確な完了条件がないループは、無限ループやコスト浪費につながります。

第13章の「無限ループに入る／タスクが曖昧」という失敗パターンは、ループ設計でも同じ問題として現れます。

15.2 スケジューリングの3方式

Claude Codeで反復実行を設計するときは、クラウド、デスクトップ定期タスク、/loopを使い分けます。

特性 クラウド（Routines） デスクトップ定期タスク /loop
実行場所 Anthropic クラウド 自分のマシン 自分のマシン
マシン起動が必要 不要 必要 必要
セッション開放が必要 不要 不要 必要
再起動をまたぐ永続 あり あり --resume で復元（未失効なら）
ローカルファイルへのアクセス 不可（毎回クリーンclone） 可 可
最小間隔 1時間 1分 1分
Tip3方式の使い分け
  • 確実に無人実行したい場合: クラウド（Routines）
  • ローカルファイルが必要な場合: デスクトップ定期タスク
  • セッション中に簡易ポーリングしたい場合: /loop

15.3 /loop コマンド

/loopは bundled skill です。間隔とプロンプトは両方任意で、何を渡すかによって挙動が変わります。

渡すもの 例 挙動
間隔＋プロンプト /loop 5m check the deploy 固定スケジュール（cron）で実行
プロンプトのみ /loop check the deploy Claudeが毎回間隔を動的に決めて実行（セルフペース）
間隔のみ／なし /loop 組み込みメンテナンスプロンプト（または loop.md）を実行

15.3.1 固定間隔

間隔を指定すると、/loopはその間隔をcron式に変換します。

指定 挙動
s / m / h / d 秒・分・時間・日として扱う
秒指定 cronは1分粒度のため、分に切り上げ
7m や 90m 綺麗に割れない値は近い値に丸められ、Claudeが採用値を知らせる

15.3.2 セルフペース

間隔を省略すると、各反復後にClaudeが1分〜1時間で次の遅延を決めます。

状況 遅延の傾向
ビルド進行中 短くなる
PRが活発 短くなる
静か 長くなる

選んだ遅延と理由は、各反復の末尾に表示されます。

動的な/loopでは、ClaudeがMonitor ツールを直接使うことがあります。バックグラウンドスクリプトの出力を行単位でストリームし、ポーリングを避けられるため、トークン効率が良い方式です。

15.3.3 組み込みメンテナンスプロンプト

プロンプトを省略すると、組み込みメンテナンスプロンプトが使われます。処理順は次の通りです。

順序 内容
1 会話の未完作業の継続
2 現ブランチのPR対応（レビューコメント・CI失敗・コンフリクト）
3 何もなければバグ探し等の掃除

新規の取り組みは始めません。pushや削除などの不可逆操作は、会話がすでに許可した範囲に限られます。

15.3.4 loop.md で既定プロンプトを差し替える

既定プロンプトは、plain Markdownのloop.mdで差し替えできます。

場所 役割
.claude/loop.md プロジェクト用。優先される
~/.claude/loop.md ユーザー用

25,000バイトを超える内容は切り詰められます。編集内容は次の反復から反映されます。

15.3.5 スキルを渡す

スキルもプロンプトに渡せます。

/loop 20m /review-pr 1234

ただし、スケジュール発火でClaudeが実行するのは、自律起動を許可されたスキルだけです。

種類 スケジュール発火時の扱い
自律起動を許可されたスキル 実行される
/permissions・/model・/clear 等の組み込み テキストとして届くだけで実行されない
disable-model-invocation: true のスキル テキストとして届くだけで実行されない

15.3.6 停止

待機中にEscを押すと、次回発火をクリアできます。

方式 停止の考え方
セルフペース タスクが完了と確認できれば、Claudeが次回を予約せず自律終了することがある
固定間隔 停止するか、7日経過まで継続

15.4 単発リマインダーとタスク管理

単発リマインダーは自然言語で作成できます。

remind me at 3pm to push the release branch
in 45 minutes, check whether the integration tests passed

単発タスクは実行後に自己削除されます。

タスクの一覧や取消も自然言語で扱えます。

やりたいこと 例
一覧を見る 予約タスクは？
取消する deploy check ジョブを取り消して

内部的には、次のツールが使われます。

ツール 役割
CronCreate 新規予約。5フィールドcron式を使う
CronList 一覧
CronDelete IDで取消

各タスクは8文字IDを持ちます。1セッションで作成できるタスクは最大50件です。

15.5 スケジュールの動作特性

Noteスケジューラの基本動作
  • スケジューラは毎秒チェックし、ターンの合間に低優先で発火する
  • 応答の途中には割り込まない
  • 時刻はローカルタイムゾーンで解釈される
  • 環境変数CLAUDE_CODE_DISABLE_CRON=1でスケジューラ全体を無効化できる（cronツールと/loopが使えなくなる）

15.5.1 ジッター

スケジュール実行にはジッターがあります。

種類 挙動
定期タスク 予定時刻から最大30分後に発火
毎時より短い間隔の定期タスク 間隔の半分まで遅れる
単発タスク 正時・半時なら最大90秒早く発火

厳密なタイミングが必要な場合は、:00や:30を避けます。

15.5.2 7日で失効

定期タスクは、作成から7日後に最後の1回を実行して自己削除します。

これは無限放置を防ぐ設計です。長期運用には、Routinesかデスクトップ定期タスクを使います。

15.6 /loop の制約

Warning/loop は起動中のセッションに依存する

タスクはClaude Codeが起動中かつidleのときだけ発火します。

ターミナルを閉じる、またはセッションを終了すると止まります。ただし、セッションをバックグラウンド化すると/loopタスクは引き継がれ、ターミナルなしで継続します。

制約 内容
catch-upなし 忙しい間に予定時刻が過ぎると、idle復帰時に1回だけ発火する。回数分は補填しない
session-scoped 新規会話を始めるとタスクは消える
復元 --resume / --continue で未失効タスクは復元される

15.7 条件達成まで回す /goal

間隔で実行するのではなく、条件を満たすまでターンを重ねて作業を続ける用途には/goalを使います。

本書では、/goalの詳細仕様までは断定しません。ここでは、スケジュール実行とは別の反復手段として位置づけます。

15.8 バックグラウンド実行と並列

長時間タスクは、バックグラウンドのセッションやエージェントで実行し、完了時に通知を受けて再開する設計にできます。

複数セッションを1画面で監視する運用もあります。ここでは概念として、次のように整理します。

設計 使いどころ
バックグラウンド実行 長時間タスクをターミナルから切り離す
完了通知 作業が終わったタイミングで人間が再開する
複数セッション監視 並列に走る作業の状態をまとめて見る

並列実行そのものの考え方は、第13章を参照してください。

15.9 自律ループの設計原則

自律ループは、便利さよりも先に制御を設計します。

原則 内容
完了条件を先に定義 曖昧なタスクは無限ループの主因になる
コストを意識する 不要なポーリングを避け、可能ならMonitorやバックグラウンド実行によるイベント駆動へ寄せる
人間をループに入れる 不可逆操作は承認または禁止に区分する
失効・上限を味方にする 7日失効や50タスク上限は暴走の安全弁として働く
ハーネスと統合する フィードバックループにスケジュール実行という時間軸の自動化を重ねる

第14章では、操作を「自動実行／承認が必要／完全禁止」に分けました。ループ設計でも同じ区分を使い、反復の中に人間の確認点を残します。

また、第14章のフィードバックループ速度階層（PostToolUse→pre-commit→CI→人間）に、スケジュール実行という時間軸の自動化を重ねることで、長時間の監視や保守を設計できます。

15.10 まとめ：ループエンジニアリングのポイント

項目 要点
ループエンジニアリングとは エージェントを反復させる設計。ハーネスは環境、ループは反復
3方式の使い分け 無人実行はクラウド、ローカルファイルが必要ならデスクトップ、セッション中の簡易ポーリングは/loop
/loopの3挙動 間隔＋プロンプト、プロンプトのみ、間隔のみ／なしで挙動が変わる
7日失効・50上限 定期タスクは7日で自己削除。1セッション最大50タスク
設計3原則 完了条件・コスト・人間をループに入れる
