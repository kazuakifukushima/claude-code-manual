16  Web版・クラウド実行：ローカル環境なしで動かす

🔵 中級者向け

第2章では、ローカルCLIの導入を扱いました。本章では、ローカルに何も入れず、ブラウザやスマホからClaude Codeを動かす方法を扱います。

具体的には：

  • 長時間タスクを投げて、後で結果を確認する
  • 手元にないリポジトリで作業する
  • 複数タスクを並列に走らせる
  • ターミナルとクラウドセッションを行き来する

16.1 ローカル環境なしで使う選択肢

Claude Codeは、同一エンジンを複数の“面（surface）”から使えます。CLAUDE.md・設定・MCPは共通です。

使い方 概要
Web版（Claude Code on the web） ブラウザclaude.ai/codeで実行。ローカル設定不要
Claude iOSアプリ スマホからタスク投入・進捗確認
デスクトップアプリ 視覚的なdiffレビュー、クラウドセッション起動、定期タスク
NoteWeb版の提供状況

Web版は research preview（2026年7月時点）で、Pro / Max / Team、および premium seat か Chat + Claude Code seat を持つ Enterprise ユーザーが対象です。

16.2 Web版の仕組みと始め方

Web版は、Anthropic管理のクラウド基盤で実行されます。ブラウザを閉じてもセッションは継続し、Claudeモバイルアプリから監視できます。

各セッションは、リポジトリをクローンした真新しいVMで動きます。使えるのは、リポジトリにコミット済みのものだけです。ローカルにだけある設定は入りません。

16.2.1 クラウドで使えるもの／使えないもの

区分 内容
使える リポジトリのCLAUDE.md
使える .claude/settings.json のhooks
使える .mcp.json のMCP
使える .claude/skills/、.claude/agents/、.claude/commands/
使える 宣言済みプラグイン
使える 組織の server-managed settings
使えない ユーザー個人の~/.claude/CLAUDE.md
使えない ~/.claude/skills/、~/.claude/agents/、~/.claude/commands/
使えない claude mcp addで入れたローカルMCP
使えない 静的APIトークン等の秘密情報（専用の秘密ストアは未提供）
使えない AWS SSO等の対話ログイン
Importantクラウドで使う設定はリポジトリにコミットする

Web版のVMはGitHubからリポジトリをcloneします。

自分の設定をクラウドで使いたい場合は、リポジトリにコミットしておくことが基本です。

16.2.2 GitHub連携の2方式

GitHub連携には、GitHub Appと/web-setupの2方式があります。

方式 概要 向いている用途
GitHub App web onboarding中にClaude GitHub Appを認可 Auto-fixを使うチーム
/web-setup ターミナルでローカルのgh CLIトークンをClaudeアカウントに同期 すでにghを使う個人

どちらの方式でも、接続GitHubアカウントが見えるリポジトリすべてにアクセスし得ます。App導入はアクセス制御そのものではありません。制限はGitHub側で行います。

16.3 ターミナルとクラウドの往復

ターミナルとクラウドは、--remoteと--teleportで行き来します。

方向 コマンド 内容
ターミナル→クラウド claude --remote 新規クラウドセッションを作成
クラウド→ターミナル claude --teleport クラウドセッションとブランチをローカルへ引き寄せる

16.3.1 ターミナルからクラウドへ：--remote

claude --remote "Fix the authentication bug in src/auth/login.ts"

--remoteは新規クラウドセッションを作成します。VMはGitHubからcloneするため、ローカルのコミットは先にpushしておきます。

特性 内容
対象 1回に1リポジトリ
作業形態 ローカルで作業を続けながら、クラウドで実行できる
進捗確認 CLIの/tasks、またはclaude.ai / モバイルアプリでセッションを開いて対話
並列 --remoteを複数回叩くと、各々独立セッションで同時実行
Tipプランは手元、実行はクラウド

先にローカルで計画を練ります。

claude --permission-mode plan

計画をリポジトリに保存・commit・pushしてから、クラウドへ実行を依頼します。

claude --remote "Execute the migration plan in docs/migration-plan.md"

戦略は手元で管理し、実行はクラウドで自律させるパターンです。

GitHub未接続リポジトリでは、ローカルをbundleしてアップロードするフォールバックがあります。100MB上限等の制約があり、bundle起動セッションはGitHub認証がないとpushできません。

16.3.2 クラウドからターミナルへ：--teleport

claude --teleport
claude --teleport <session-id>

セッション内では/teleportまたは/tpを使えます。/tasksからtでも可能です。

--teleportは、ブランチをfetch/checkoutし、会話履歴をターミナルに読み込みます。

比較 内容
--teleport クラウドセッションとそのブランチを引き寄せる
--resume このマシンのローカル履歴を再開する
Warningハンドオフは片方向

CLIからのハンドオフはクラウド→ターミナルの片方向です。既存ターミナルセッションをwebへ送ることはできません。

また、teleportにはclaude.aiサブスク認証が必要です。APIキー / Bedrock / Vertex / Foundry認証では使えません。/loginでclaude.ai認証へ切り替えます。

--remoteはクラウドセッション作成、--remote-controlはローカルCLIをwebから監視する別機能のRemote Controlです。名前が似ていますが、別の機能として扱います。

16.4 ローカルCLIとの違い

第2章のローカルCLIと、Web版・クラウド実行の違いを整理します。

観点 ローカルCLI（第2章） Web版・クラウド実行
セットアップ インストール必要 不要（ブラウザのみ）
ファイルアクセス ローカルファイル直接 GitHubクローンのみ（ローカル不可）
長時間タスク 端末を開いておく必要 閉じても継続
並列 worktree等で自前構成 --remoteを複数投入
権限プロンプト 対話で承認 自律実行（下記コスト/安全注意）
リソース上限 マシン依存 4 vCPU / 16GB RAM / 30GB ディスク（目安、変動あり）

16.5 便利機能

16.5.1 Auto-fix PR

Auto-fix PRは、PRを監視し、CI失敗やレビューコメントに自動対応する機能です。Claude GitHub Appが必要です。

ターミナルからは次のコマンドを使います。

/autofix-pr
WarningPRコメントで自動化が走るリポジトリ

PRコメントをきっかけにAtlantis等が走るリポジトリでは、Auto-fix PRの運用に注意が必要です。

16.5.2 セッションの共有・アーカイブ・削除

セッションの共有・アーカイブ・削除は、claude.ai/codeのサイドバーから行えます。

共有時は、認証情報や非公開リポジトリのコードが含まれ得るため、中身を確認します。Max / Proは既定でリポジトリアクセス検証が無効です。

16.5.3 クラウドセッションでのコンテキスト管理

コマンド クラウドセッションでの扱い
/compact 使用可
/context 使用可
/clear 使用不可。新規セッションを作る

16.6 セキュリティ・分離・コスト

Web版・クラウド実行では、実行環境が自分のマシンではなくAnthropic管理の基盤になります。ローカルCLIとは異なる前提で、安全性とコストを見ます。

16.6.1 分離

各セッションは隔離VMで動きます。git認証情報や署名鍵はサンドボックス内に置かれず、scoped credentialとプロキシで処理されます。

ネットワークは既定で制限されます。設定名として、None / Trusted / Full / Customがあります。

ネットワークを無効にしてもAnthropic APIとは通信するため、データがVM外に出得る点に留意します。

16.6.2 秘密情報

専用の秘密ストアは未提供です。環境変数やsetup scriptは、当該環境を編集できる人に見えます。

秘密を入れる場合は、その可視性を前提に扱います。

Importantクラウド実行のコストと制限

クラウドVMに別途の計算課金はありません。

ただし、レート制限はアカウント全体で共有されます。並列実行はレート制限を比例的に消費します。

また、組織のIP allowlistが有効だと、クラウドセッションは認証エラーになります。Anthropic管理基盤から発信されるためです。

Warning医療・機密データを扱う場合

臨床データ、PHI/PII、機関機密を扱う場合は、クラウドセッションやサードパーティ連携に載せないでください。

第12章や本書のセキュリティ方針に沿って、扱うデータを分けます。
